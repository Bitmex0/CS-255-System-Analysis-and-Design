DriverPass Project Summary

The DriverPass project focused on designing a system for a small business that wanted to improve how students prepare for their driving tests. The client needed a platform where students could schedule driving lessons, access practice tests, and interact with instructors and administrators. My role was to interpret the client's goals, translate them into clear business requirements, and design a system architecture that supports those needs.

What I Did Well

One thing I did particularly well was breaking down the client's needs into structured, actionable requirements. I made sure each requirement was measurable and tied directly to a user or business goal. That clarity made the system design phase much smoother because the diagrams and architecture naturally aligned with the requirements.

What I Would Revise

If I were to revise one part of my work, I would refine the nonfunctional requirements section. I covered the essentials, but I would strengthen it by adding more details around scalability and security. These areas are critical in modern system, and expanding them would make the documentation even stronger.

Interpreting User Needs

Interpreting the user's needs require careful attention to the interview transcripts and the client's pain points. Issues like scheduling inefficiencies and limited access to practice tests became direct inputs into the system's features and workflows.

Considering user needs is essential because a system can be technically sound but still fail if it doesn't solve the right problems. Designing with the user in mind ensures the final product is practical, usable, and aligned with real-world expectations.

My Approach to Software Design

My approach to designing software is grounded in:

Analysis - understanding the problem space and clarifying requirements
Iteration - refining ideas as the system becomes clearer
Visual modeling - using activity diagrams, sequence diagrams, and class diagrams to visualize system behavior
User-centered design - ensuring the system aligns with actual user needs
Structured modeling - separating functional and non-functional requirements for clarity
This combination helps create systems that are both practical and maintainable. It's an approach I plan to continue using in future projects.
